# MS101 remote-proof-server

**Severity:** critical · **Confidence:** medium · **Applies to:** TypeScript / JavaScript

## What it finds

A proof server URL (a string next to `proofServer`, `httpClientProofProvider(...)`, or any URL on port 6300) that points to a host other than `localhost`, `127.0.0.1`, `::1`, `host.docker.internal` or a Docker service named `proof-server`.

## Why it matters

To build a proof, the proof server receives the user's private inputs (witness values) in plain form. A proof server on someone else's machine sees every private value of every user who uses it. Midnight's documentation tells you to use only a proof server you control.

## Example

```ts
const proofProvider = httpClientProofProvider("https://proofs.example.com:6300"); // MS101
```

## Fix

Run the proof server on the user's machine, and make the URL configurable:

```ts
const proofProvider = httpClientProofProvider(process.env.MIDNIGHT_PROOF_SERVER ?? "http://localhost:6300");
```

## Not flagged

- Other remote URLs (indexer, node, faucet): they only see public data.
- Test files (`*.test.ts`, `*.spec.ts`, and files under `test/`, `tests/`, `__tests__/`), which often use fake remote servers on purpose.

Turn off all TypeScript checks with `--no-sdk` or `"sdk": false` in the config file.

## Known limits

- The proof-server URL must be a string literal near a name containing "proof", or use port 6300. A URL read from configuration at runtime (an environment variable) is not checked, which is usually the right setup.
