# MS008 missing-nullifier

**Severity:** medium

## What it finds

An exported circuit that authorizes the caller with an anonymous Merkle membership proof (`tree.checkRoot(...)` over private data) and then changes ledger state, without ever asserting that some value is **not** yet in a set (a nullifier check).

## Why it matters

A Merkle membership proof says "I am one of the members" without saying which one. That is the point, but it also means the contract cannot tell whether the same member already acted. Without a nullifier, one member can vote, claim, or withdraw as many times as they like.

## Example

```compact
export ledger voters: MerkleTree<10, Bytes<32>>;
export ledger yes: Counter;
witness secretKey(): Bytes<32>;
witness voterPath(): MerkleTreePath<10, Bytes<32>>;

circuit voterLeaf(sk: Bytes<32>): Bytes<32> {
  return persistentHash<Vector<2, Bytes<32>>>([pad(32, "myapp:voter:"), sk]);
}

export circuit voteYes(): [] {
  const path = voterPath();
  assert(disclose(path.leaf == voterLeaf(secretKey())), "not your path");
  assert(voters.checkRoot(disclose(merkleTreePathRoot<10, Bytes<32>>(path))), "not a voter"); // MS008
  yes.increment(1);
}
```

## Fix

Derive a nullifier that is unique per member (and per action), check it, and record it:

```compact
export ledger used: Set<Bytes<32>>;

export circuit voteYes(): [] {
  const path = voterPath();
  assert(disclose(path.leaf == voterLeaf(secretKey())), "not your path");
  assert(voters.checkRoot(disclose(merkleTreePathRoot<10, Bytes<32>>(path))), "not a voter");
  const n = disclose(persistentHash<Vector<2, Bytes<32>>>([pad(32, "myapp:vote:"), secretKey()]));
  assert(!used.member(n), "already voted");
  used.insert(n);
  yes.increment(1);
}
```

This follows the nullifier pattern in the [Midnight security best practices](https://docs.midnight.network/guides/security-best-practices): store used nullifiers in a `Set`.

## Not flagged

- Circuits that check a nullifier (`assert(!set.member(...))`) anywhere in the circuit or its helpers.
- Membership checks with `Set.member(...)`: these are usually role or allowlist checks where repeating is intended.
- Circuits that do not change ledger state.

If repeating the action is intended, suppress with `// shield-disable-next-line MS008`.
- A circuit whose only write is `map.insert(key, value)` with a key derived from the caller's secret, even when the key was passed through `disclose()` first: repeating it rewrites the same entry.

## Known limits

- A write keyed by a hash of the caller's secret (`attestations.insert(hash(secret, …), value)`) that does not read the old value is the same entry every time, so it is not reported.
- A nullifier counts when the circuit both checks and inserts into a `Set`. A nullifier kept in a `Map` or a custom structure is not recognized and may be reported.
