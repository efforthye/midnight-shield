# MS018 nullifier-not-checked

**Severity:** high · **Confidence:** medium · **Applies to:** Compact

## What it finds

A nullifier set (a ledger `Set` named like `nullifiers`, `spent`, `used`, `claimed`, `voted`) that an exported circuit adds to without checking membership first, or checks with `assert(!set.member(n))` without ever adding to.

## Why it matters

Inserting into a `Set` twice does not fail, and a check without an insert passes every time. Either way the same nullifier can be used again: a double spend or a second vote.

## Example

```compact
spent.insert(disclose(n)); // no assert(!spent.member(n)) first
```

## Fix

```compact
assert(!spent.member(n), "already spent");
spent.insert(n);
```

## Not flagged / known limits

Sets with neutral names (`seen`, `items`) and no membership check are not treated as nullifier sets: an ordinary set insertion looks the same. Deny lists (`assert(!blacklist.member(id))`) are not flagged.

## Known limits

- A set counts as a nullifier set by its name (`nullifiers`, `spent`, `used`, `claimed`, `voted`, …), or, whatever its name, when it receives hashes of the caller's secret and no circuit ever checks membership in it (low confidence).
- Deny lists (`assert(!blacklist.member(id))`) are not flagged.
