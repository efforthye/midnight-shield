# MS037 self-satisfiable-check

**Severity:** high · **Confidence:** medium · **Applies to:** Compact

## What it finds

An `assert` whose comparison involves only values the prover chooses:

- results of witnesses, and
- parameters of the exported circuit (they are private inputs, chosen by whoever builds the proof),

with nothing in it that the prover does not choose: no ledger value, no constant, no hash or signature. At least one witness has to be involved, and none of the values may be tied to something trusted by another check in the same circuit. Comparisons inside helper circuits are followed.

## Why it matters

A zero-knowledge proof shows that the prover knows values that satisfy the circuit. If every value in a check is the prover's to pick, they simply pick values that pass. The check reads like a guarantee ("the rating is at least the threshold", "the collateral covers the loan"), but the proof guarantees nothing. This is the Compact form of the under-constrained bugs that Circomspect and Picus look for in Circom circuits.

## Example

```compact
witness reportedScore(): Uint<16>;

export circuit proveScoreAbove(threshold: Uint<16>): [] {
  assert(reportedScore() >= threshold, "score too low");   // MS037
  proofs.increment(1);
}
```

The prover's DApp returns any rating it likes from `reportedScore()`.

## Fix

Tie at least one side to something the prover cannot choose:

```compact
export ledger ratings: Map<Bytes<32>, Uint<16>>;

export circuit proveScoreAbove(threshold: Uint<16>): [] {
  assert(ratings.lookup(disclose(myId())) >= threshold, "score too low");
  proofs.increment(1);
}
```

Other ways: compare the witness with a ledger value first (`assert(price() == oraclePrice)`), open a commitment stored on the ledger, or verify a signature from a key stored on the ledger.

## Not flagged / known limits

- Checks with a constant (`assert(age() >= 18)`): the bound is real, even if the witness value may not be. MS002 covers witness values that reach public state unchecked.
- Hash and signature checks (`hash(secretKey()) == publicId`): knowing a preimage or a key is a real proof.
- Values tied to the ledger by another check in the same circuit.
- An `assert` on a witness's Boolean result: MS013 reports it.
- Circuits that change nothing (no ledger write, no transfer): a pure query cannot be abused this way.

See `--print witnesses` for every prover-chosen value, where it goes and what constrains it.
