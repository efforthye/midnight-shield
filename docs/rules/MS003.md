# MS003 low-entropy-hash

**Severity:** high

## What it finds

A `persistentHash` / `transientHash` whose private inputs have little entropy (32 bits or less in total), and whose result is made public. Constant inputs (such as a `pad(...)` tag) and public ledger values add no entropy.

## Why it matters

A hash hides nothing if the input has few possible values. For a vote (`YES` / `NO`), an age (`Uint<8>`) or a PIN (`Uint<16>`), anyone can hash every candidate and compare with the public hash. Declaring the disclosure with `disclose()` does not make the value secret.

## Example

```compact
witness myVote(): Vote;
export ledger ballots: Set<Bytes<32>>;

export circuit castVote(): [] {
  const h = persistentHash<Vector<2, Bytes<32>>>([pad(32, "vote:"), myVote() as Field as Bytes<32>]);
  ballots.insert(disclose(h)); // MS003
}
```

## Fix

Use a commitment with fresh secret randomness:

```compact
witness randomness(): Bytes<32>;

export circuit castVote(): [] {
  ballots.insert(persistentCommit<Vote>(myVote(), randomness()));
}
```

Or include a high-entropy secret (such as a 32-byte secret key) in the hash.

## How entropy is estimated

`Boolean` = 1 bit, `Uint<n>` = n bits, `Uint<a..b>` = log2(b - a), enums = log2(member count), `Bytes<n>` = 8n bits, `Field` = 254 bits. Casts keep the smaller of the value's and the target type's entropy. Values of unknown type are treated as high-entropy, so the rule does not guess.

## Known limits

- Entropy comes from the declared type. A `Bytes<32>` that actually holds a small number (a PIN padded to 32 bytes) is treated as high entropy.
