# MS004 weak-commitment-randomness

**Severity:** high (reuse: medium)

## What it finds

A `persistentCommit` / `transientCommit` whose randomness (second argument) is:

- constant, such as `pad(32, "salt")` or `default<Bytes<32>>`,
- read from public ledger state,
- a local value the same circuit also makes public (writes to the ledger, discloses or returns), such as `persistentCommit(category, c)` where `c` is also a ledger key; not reported when the committed value is a 32-byte secret, which cannot be guessed either way,
- short (less than 128 bits of entropy), or
- the same expression used by another commitment of a different value in the same circuit.

## Why it matters

A commitment only hides the value if the randomness is secret and unpredictable. With known randomness, anyone can recompute the commitment for every candidate value. Reused randomness lets observers link commitments to each other.

## Example

```compact
export ledger salt: Bytes<32>;
export ledger committed: Bytes<32>;

export circuit commitAmount(amount: Uint<64>): [] {
  committed = persistentCommit<Uint<64>>(amount, salt); // MS004: public randomness
}
```

## Fix

Take fresh 32-byte randomness from a witness for every commitment:

```compact
witness randomness(): Bytes<32>;

export circuit commitAmount(amount: Uint<64>): [] {
  committed = persistentCommit<Uint<64>>(amount, randomness());
}
```

If you need several commitments from one seed, derive separate randomness per use, e.g. `persistentHash([pad(32, "myapp:commit:a"), seed])`.

## Known limits

- Reuse means the same local value or the same stored value used for two commitments. Two calls of a randomness witness are separate values, because a witness can return fresh bytes on every call; whether it does is checked by MS121 when the DApp is scanned too.
