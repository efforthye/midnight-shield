# MS011 unguarded-auth-update

**Severity:** high · **Confidence:** medium · **Applies to:** Compact

## What it finds

An exported circuit that changes a ledger field the contract uses to authorize callers, when nothing in that circuit checks who is calling.

A field counts as an authorization field when some `assert` compares it with a caller identity, for example `assert(deriveId(secretKey()) == ownerId, …)`, or uses it as an allow-list, for example `assert(admins.member(deriveId(secretKey())), …)`. A change is an assignment (`ownerId = …`) or a state-changing method (`admins.insert(…)`, `remove`, `write`, …), also inside helper circuits in the same file.

## Why it matters

Exported circuits can be called by anyone. If the circuit that replaces the owner, or adds an admin, does not check the caller, anyone can make themselves the owner or an admin, and every check that relies on that field is bypassed.

## Example

```compact
export ledger ownerId: Bytes<32>;

export circuit withdraw(): [] {
  assert(deriveId(secretKey()) == ownerId, "not the owner");
}

export circuit setOwner(newOwnerId: Bytes<32>): [] {
  ownerId = disclose(newOwnerId); // MS011: anyone can call this
}
```

## Fix

Check the caller first, in the same way the rest of the contract does:

```compact
export circuit transferOwnership(newOwnerId: Bytes<32>): [] {
  assert(deriveId(secretKey()) == ownerId, "not the owner");
  ownerId = disclose(newOwnerId);
}
```

## Not flagged

- The constructor, which runs once at deployment.
- Circuits that contain any `assert`, directly or in a helper circuit they call.
- Circuits that call a circuit from an imported module (such as an `assertOnlyOwner()`), which may check the caller.
- Fields compared only with constants or parameters (state machines such as `assert(state == State.OPEN)`, or existence checks such as `scores.member(disclose(id))`).
- Merkle tree membership: open registration into an anonymity set is a common, intended design.
