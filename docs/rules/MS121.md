# MS121 weak-witness-implementation

**Severity:** critical · **Confidence:** high · **Applies to:** Compact and TypeScript together

## What it finds

When a scan covers a contract and its DApp, Midnight Shield finds what the contract uses each witness for, then reads the TypeScript `witnesses = { … }` object that implements them:

- a witness passed as the randomness of `persistentCommit` / `transientCommit` is **commitment randomness**;
- a `Bytes<32>` witness hashed into ledger state is a **secret key**.

It reports an implementation of such a witness that returns a newly allocated buffer (all zeros), a clock value, `Math.random()`, or a constant written in the code.

## Why it matters

The contract's privacy rests on these values being random and known only to the user, but the contract cannot check that: the witness runs in the DApp. A zero salt lets anyone open every commitment; a constant key lets anyone act as every user. Neither file shows the bug on its own, and the witness name often does not say what it is for (`bidSalt`, `extra`, `k`), which is why the name-based MS113 can miss it.

## Example

```compact
witness bidExtra(): Bytes<32>;
export circuit bid(v: Uint<64>): [] {
  sealed = disclose(persistentCommit<Uint<64>>(v, bidExtra()));
}
```

```ts
export const witnesses = {
  bidExtra: ({ privateState }) => [privateState, new Uint8Array(32)], // MS121
};
```

## Fix

```ts
export const witnesses = {
  bidExtra: ({ privateState }) => [privateState, crypto.getRandomValues(new Uint8Array(32))],
};
```

Keep the value in private state if the contract needs the same randomness later (to open the commitment).

## Not flagged / known limits

- Implementations that read the value from private state (`privateState.secretKey`) or use a random source.
- Only runs when the contract and the DApp are scanned together (the CLI and the GitHub Action on a folder that holds both). The playground checks files one at a time.
- When MS113 already reports the same line by name, MS121 is not repeated.
