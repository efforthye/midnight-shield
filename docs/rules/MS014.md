# MS014 commitment-randomness-disclosed

**Severity:** high · **Confidence:** medium · **Applies to:** Compact

## What it finds

A witness used as the randomness of `persistentCommit` or `transientCommit` somewhere in the file, which another circuit discloses as is.

## Why it matters

A commitment hides its value only while the randomness is secret. Once the randomness is public, anyone can try candidate values (bids, votes, small amounts) until one matches, and the commitment no longer hides anything.

## Example

```compact
export circuit placeBid(amount: Uint<64>): [] {
  sealedBid = disclose(persistentCommit<Uint<64>>(amount, bidRandomness()));
}

export circuit publishSalt(): [] {
  revealedSalt = disclose(bidRandomness()); // MS014
}
```

## Fix

Open the commitment inside a circuit, so the randomness is used but not published:

```compact
export circuit revealBid(amount: Uint<64>): [] {
  assert(disclose(persistentCommit<Uint<64>>(amount, bidRandomness()) == sealedBid), "does not match");
  winningBid = disclose(amount);
}
```

## Not flagged

- Circuits that check a commitment in an `assert` (a deliberate commit-reveal opening).
- A commitment whose value is a secret 32-byte witness (`persistentCommit(ownerSecret(), key)`): knowing the randomness does not help anyone guess the value, so it works as a keyed binding. Values with few possibilities (a ballot, a choice) are still reported.

## Known limits

- Recognizes randomness from a witness (anywhere in the file) and from a circuit parameter disclosed in the same circuit. Randomness derived from another value first (`persistentHash(r)`) is not followed.
