# MS027 ignored-check-result

**Severity:** high · **Confidence:** high · **Applies to:** Compact

## What it finds

A Boolean check called as a statement, so its result is thrown away: `set.member(x);`, `tree.checkRoot(r);`, `blockTimeLessThan(t);`, or a helper named like a check (`isValid`, `hasRole`, `checkX`). Mapped from Slither's `unused-return`.

## Why it matters

The code reads like a check, but nothing is enforced.

## Example

```compact
ballots.member(n);  // result ignored
ballots.insert(n);
```

## Fix

```compact
assert(!ballots.member(n), "already voted");
```

## Not flagged / known limits

Helpers whose names do not look like checks (`_grantRole` returning whether the role was new) are not flagged.
