# MS002 unconstrained-witness

**Severity:** medium

## What it finds

A witness whose result reaches public state (through `disclose()` or a ledger write) while no `assert` or `if` anywhere in the file checks its value.

## Why it matters

Witnesses run on the user's machine, and the prover can return any value. A circuit that publishes a witness value without checking it lets the user write whatever they want to the ledger: a fake balance, a fake score, a fake state.

## Example

```compact
witness myBalance(): Uint<64>;
export ledger balance: Uint<64>;

export circuit syncBalance(): [] {
  balance = disclose(myBalance()); // MS002
}
```

## Fix

Constrain the value before trusting it: bound its range, check membership in a ledger set or Merkle tree, or check its relation to existing ledger state.

```compact
export circuit syncBalance(): [] {
  const b = myBalance();
  assert(b <= 1000000, "balance out of range");
  balance = disclose(b);
}
```

## Not flagged

To keep noise low, the rule only checks witnesses that report facts: `Boolean`, `Uint`, `Field`, enums, and structs or tuples that contain them. It skips:

- free-form data such as `Bytes<n>` and `Opaque` (names, messages, keys),
- witnesses whose name suggests randomness (`rand`, `salt`, `nonce`, `seed`, `entropy`, `blind`),
- values that pass through a hash or commitment before becoming public.
