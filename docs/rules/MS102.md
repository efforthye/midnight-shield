# MS102 secret-in-log

**Severity:** high · **Confidence:** medium · **Applies to:** TypeScript / JavaScript

## What it finds

A value whose name says it is a secret (`seed`, `secretKey`, `mnemonic`, `password`, `privateKey`, `sk`) passed directly to `console.*`, `logger.*` or `log.*`, including inside a template string (`` `${seed}` ``).

## Why it matters

Logs are copied to CI output, crash reporters, log services and browser consoles, and they are kept for a long time. A wallet seed in a log gives anyone who reads the log full control of the wallet.

## Example

```ts
console.log(`restoring wallet from ${seed}`); // MS102
```

## Fix

Log something that cannot be turned back into the secret:

```ts
console.log(`restoring wallet for ${publicKeyOf(seed)}`);
```

## Not flagged

- A secret passed through another call first (`publicKeyOf(seed)`), which is treated as a derived value.
- Metadata of a secret: `seed.length`, `secret.kind`, `secret.type`.
- Test files.
