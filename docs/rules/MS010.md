# MS010 linkable-ledger-update

**Severity:** medium · **Confidence:** medium

## What it finds

In a contract where members act anonymously (an exported circuit authorizes with a Merkle membership proof), the same identifier, derived only from a member's secret, is published by two or more circuits.

## Why it matters

Anonymous membership hides *which* member acted. But if every circuit publishes the same tag for a member (for example `hash("tag", secretKey)`), anyone can group all actions with the same tag and link them to one person, even without knowing who that person is. Over time that is often enough to identify them.

## Example

```compact
circuit memberTag(sk: Bytes<32>): Bytes<32> {
  return persistentHash<Vector<2, Bytes<32>>>([pad(32, "app:tag:"), sk]);
}

export circuit post(): [] {
  // ... Merkle membership proof ...
  posts.insert(disclose(memberTag(secretKey())));      // MS010
}

export circuit react(): [] {
  // ... Merkle membership proof ...
  reactions.insert(disclose(memberTag(secretKey())));  // same tag again
}
```

## Fix

Give each action its own domain, so the values cannot be matched across circuits:

```compact
posts.insert(disclose(persistentHash<Vector<2, Bytes<32>>>([pad(32, "app:post:"), sk])));
reactions.insert(disclose(persistentHash<Vector<2, Bytes<32>>>([pad(32, "app:react:"), sk])));
```

If even two posts by the same member should be unlinkable, also mix in something that changes per action (a round number or a post ID).

## Not flagged

- Account-style contracts (tokens, access control) without anonymous membership: a stable account identifier is linkable by design, like an address.
- Identifiers that include fresh randomness or a value that differs per circuit.
- Identifiers published by a single circuit.
