# MS105 insecure-randomness

**Severity:** high · **Confidence:** medium · **Applies to:** DApp TypeScript / JavaScript

## What it finds

`Math.random()` used to make a value whose name says it is a secret, seed, nonce, salt or commitment randomness (by the variable or property it is assigned to, or the function it is returned from).

## Why it matters

`Math.random()` is not cryptographically secure: its output can be predicted from earlier outputs. Predictable commitment randomness lets others open commitments, and a predictable key or seed can be recomputed.

## Example

```ts
export function newBidRandomness(): string {
  return Math.random().toString(16).slice(2); // MS105
}
```

## Fix

```ts
export function newBidRandomness(): Uint8Array {
  return crypto.getRandomValues(new Uint8Array(32));
}
```

## Not flagged

- `Math.random()` for UI values (delays, colors, animation), whose names do not suggest a secret.
- `Math.random()` as a sort comparator (`xs.sort(() => Math.random() - 0.5)`): it shuffles an order and makes no value.

## Known limits

- Follows `Math.random()` through a variable or a wrapper function, within one file. The value must end up in a name like a secret, nonce, salt or randomness; "random" on its own (`randomHex`, `randomDelay`) does not count.
- `Math.random()` in the `else` branch of a `crypto.getRandomValues` check (a fallback for environments without crypto) is not reported.
