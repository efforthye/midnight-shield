# MS038 free-nullifier

**Severity:** high · **Confidence:** medium · **Applies to:** Compact

## What it finds

A once-only check (`assert(!used.member(n))` followed by `used.insert(n)`, on a set or a map that only records use) where `n` is built from witness values that nothing else in the circuit pins down:

- no membership proof covers them (a Merkle path whose leaf is bound to them, a `member` check on a registered set), and
- no equality ties them to the ledger or a constant, directly or through other pinned values (`hash(sk) == ownerId`, `path.leaf == key(sk)` with the path in the tree).

The nullifier can be a witness itself, a hash of a witness secret, or a parameter that an equality ties to such a hash.

## Why it matters

A nullifier only stops repeats when the prover cannot change it. If it comes from a secret that is not registered anywhere, the prover picks a new secret, gets a new nullifier, and does the "once only" action again: votes twice, claims twice, mints twice with a new replay key. This is the bug class behind double spends found in large ZK systems: Aztec 2.0 (a note index not range-checked, so one note had several nullifiers) and 0xPARC's StealthDrop (a signature used as the nullifier, and signatures are not unique).

## Example

```compact
witness claimSecret(): Bytes<32>;
export circuit claim(): [] {
  const nul = persistentHash<Vector<2, Bytes<32>>>([pad(32, "app:nul:"), claimSecret()]);
  assert(!claimed.member(disclose(nul)), "already claimed");   // MS038
  claimed.insert(disclose(nul));
  paid.increment(1);
}
```

A replay key taken from a separate witness instead of the signed message has the same flaw:

```compact
assert(verifySignature(keccak256(msg), sig) == signer, "not attested");
const nonce = messageNonce();          // not part of msg
assert(!usedNonces.member(disclose(nonce)), "nonce already used");   // MS038
```

## Fix

Derive the nullifier from a secret that the circuit already binds, plus fixed context:

```compact
const sk = voterSecret();
const leaf = persistentHash<Vector<2, Bytes<32>>>([pad(32, "app:leaf:"), sk]);
const path = voterPath(leaf);
assert(path.leaf == leaf, "path is not yours");
assert(voters.checkRoot(disclose(merkleTreePathRoot<10, Bytes<32>>(path))), "not a voter");
const nul = persistentHash<Vector<3, Bytes<32>>>([pad(32, "app:nul:"), sk, electionId]);
```

For a replay key, take it out of the attested message rather than from its own witness.

## Not flagged / known limits

- A nullifier that mixes a pinned secret with a free request id (`hash(agentSecret, requestId())` after an agent check): a per-request token, by design.
- Another once-only check in the same circuit whose value is pinned (a payroll row claimed once).
- Sign-up circuits (`register`, `enroll`, "already registered"): every new secret is a new account on purpose.
- Key registries (the same value also added to another set or tree) and maps that store data under the key.
- Actions paid with a coin (`receive…`), where a new identity simply pays again.
- When the leaf is not bound to the caller, MS009 is usually reported on the same circuit as well.
- Parameters are not treated as free on their own: an epoch or election id is often meant to vary.
