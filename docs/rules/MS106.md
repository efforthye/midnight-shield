# MS106 secret-sent-over-network

**Severity:** high · **Confidence:** medium · **Applies to:** DApp TypeScript / JavaScript

## What it finds

A variable named like a secret (seed, secret key, mnemonic, private state) passed to `fetch`, `axios`, `got`, `ky` or a `.get/.post/.put/…` call on an HTTP client, in the URL or the body.

## Why it matters

Whoever runs the server, a proxy in between, or an analytics or logging service can read and keep the secret. In Midnight, secrets and private state should stay on the user's device; the chain only needs proofs.

## Example

```ts
await fetch(`https://backup.example.com/save?seed=${seed}`); // MS106
```

## Fix

Send something derived from the secret instead, such as a public key, a signature or a hash. If you need a backup, encrypt it on the device with a key the server does not have.

```ts
await fetch(url, { method: "POST", body: JSON.stringify({ publicKey: publicKeyOf(seed) }) });
```

## Not flagged

- Values computed from a secret by another function (`publicKeyOf(seed)`, `hashSecret(secretKey)`), and safe properties such as `seed.length`.

## Known limits

- Checks `fetch`, `axios`, `got`, `ky`, `request`, HTTP clients (`http`, `https`, `client`, `api`) and sockets (`ws.send`, `socket.send`, …). A secret passed through another function first (`publicKeyOf(seed)`) counts as derived and is not reported.
