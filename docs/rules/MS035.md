# MS035 inconsistent-guard

**Severity:** high · **Confidence:** medium · **Applies to:** Compact

## What it finds

A ledger field that holds one value (not a `Map`, `Set`, `List`, `Counter` or Merkle tree), where:

1. one exported circuit checks the caller before changing it (a secret, an allow-list, a signature, a Merkle proof, or an imported check such as `assertOnlyOwner()`), and
2. another exported circuit overwrites it with no caller check at all.

The guarded circuit tells us the field is meant to be protected. The other circuit is the way around it. This is the idea behind Slither's `protected-vars` detector. Slither needs a `@custom:security write-protection` comment to know which variables are protected. Here, the guarded writer plays the role of the annotation.

## Why it matters

Usually the check was added to the circuit that was written first, and a later circuit (a reset, a migration, a "convenience" setter) forgot it. Every caller then has a path to the field that skips the check.

## Example

```compact
export ledger fee: Uint<64>;

export circuit setFee(f: Uint<64>): [] {
  assert(deriveId(secretKey()) == ownerId, "not owner");
  fee = disclose(f);
}

export circuit resetFee(): [] {
  fee = 0;                               // MS035: anyone can change the fee here
}
```

## Fix

Add the same check to the second circuit:

```compact
export circuit resetFee(): [] {
  assert(deriveId(secretKey()) == ownerId, "not owner");
  fee = 0;
}
```

If the second circuit is only a building block, stop exporting it: rename it to `_resetFee` and call it from a circuit that checks the caller.

## Not flagged / known limits

- Collections (`Map`, `Set`, `List`, `Counter`, Merkle trees). Different circuits normally write different entries (a deposit adds to a balance, a withdrawal checks the owner), so different checks are expected.
- State transitions and one-time setup: the unchecked circuit asserts on a field it also changes (`assert(phase == 0); phase = 1`, or `assert(!initialized); initialized = true`).
- Writes that MS011 (owner fields) or MS034 (a field another circuit trusts) already report.
- Circuits inside a `module`, and circuits named with a leading `_`.
- Updates such as `+=` or `.increment()`: only writes that replace the whole value are compared.

See the access map (`--print access`) for the full picture of who can call what.
