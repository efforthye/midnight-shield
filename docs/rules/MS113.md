# MS113 weak-witness-randomness

**Severity:** critical · **Confidence:** medium · **Applies to:** TypeScript / JavaScript

## What it finds

Inside a `witnesses = { … }` object, a witness named like randomness or a secret (`bidRandomness`, `nonce`, `salt`, `secretKey`) whose implementation returns a newly allocated buffer (`new Uint8Array(32)`, `Buffer.alloc(32)`, all zeros) or a clock value (`Date.now()`), and nothing random.

## Why it matters

This links the DApp to the contract: the contract trusts the witness to supply secret randomness, and the TypeScript decides what it really is. Zero bytes are the same for everyone, and a timestamp can be guessed, so every commitment made with them can be opened by trying candidate values. Only possible to see on Midnight, where witnesses are implemented in the DApp.

## Example

```ts
export const witnesses = {
  bidRandomness: ({ privateState }) => [privateState, new Uint8Array(32)],
};
```

## Fix

```ts
export const witnesses = {
  bidRandomness: ({ privateState }) => [privateState, crypto.getRandomValues(new Uint8Array(32))],
};
```

## Not flagged / known limits

- Implementations that read the value from private state (the usual, correct pattern) are not flagged.
- A buffer filled in a helper function defined elsewhere is not followed.
