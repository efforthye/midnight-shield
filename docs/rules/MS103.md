# MS103 hardcoded-secret

**Severity:** critical · **Confidence:** medium · **Applies to:** TypeScript / JavaScript

## What it finds

A string literal that looks like real key material, assigned to a variable or property with a secret-like name (`seed`, `secretKey`, `privateKey`, `mnemonic`, `password`, …):

- 32 bytes in hex (64 hex digits, with or without `0x`), or
- a recovery phrase of 12, 15, 18, 21 or 24 lowercase words.

## Why it matters

Anything in the source is readable by everyone who can see the repository, and anything in a web app's bundle is readable by every visitor. A seed or key written there can be used by anyone to sign as that wallet. Removing it in a later commit does not help: it stays in the git history.

## Example

```ts
export const walletConfig = {
  seed: "9f3c2a7e5b1d4c8f6a0e2b9d7c5f1a3e8b6d4f2a0c9e7b5d3f1a8c6e4b2d0f97", // MS103
};
```

## Fix

Load secrets at run time, from an environment variable, a secret manager, or the user's wallet, and treat the exposed one as leaked (move funds, rotate the key):

```ts
export const walletConfig = {
  seed: process.env.WALLET_SEED ?? "",
};
```

## Not flagged

- Well-known low-entropy development seeds such as `000…0001`, and test phrases with few distinct words such as `abandon … about`.
- Values with other names (`txHash`, `contractAddress`).
- Test files (`*.test.ts`, `*.spec.ts`, and files under `test/`, `tests/`, `__tests__/`).
