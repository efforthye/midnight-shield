# MS007 disclosed-secret

**Severity:** high · **Confidence:** low (the rule relies on names)

## What it finds

The raw value of a witness or circuit parameter whose name says it is a secret (`secretKey`, `localSk`, `_secret`, `seed`, `mnemonic`, `password`, `privateKey`) reaching `disclose()` or a ledger write.

## Why it matters

Everything disclosed is visible to anyone who reads the chain. A secret key that is published once can be used by anyone, forever.

This often happens when `disclose()` is added only to make a compiler error go away, which is a common pattern in AI-generated code.

## Example

```compact
witness secretKey(): Bytes<32>;
export ledger owner: Bytes<32>;

constructor() {
  owner = disclose(secretKey()); // MS007
}
```

## Fix

Publish a domain-separated hash of the secret (a public identifier), and keep the secret itself private:

```compact
circuit deriveId(sk: Bytes<32>): Bytes<32> {
  return persistentHash<Vector<2, Bytes<32>>>([pad(32, "myapp:owner:"), sk]);
}

constructor() {
  owner = disclose(deriveId(secretKey()));
}
```

## Not flagged

- Hashes, commitments, and other values derived from the secret (for example a public key computed with a standard-library function).
- Comparisons that involve the secret, such as `assert(deriveId(sk) == owner)`: they reveal one bit, not the secret.
- Witnesses and parameters whose names do not look secret. Name your secrets clearly so the rule can protect them.

## Known limits

- Secrets are recognized by name (`secretKey`, `sk`, `seed`, `privKey`, `mnemonic`, `password`, …). A secret witness with a neutral name (`getUserMaterial()`) is missed here; MS002 still reports the unchecked value reaching public state.
