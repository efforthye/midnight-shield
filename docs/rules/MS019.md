# MS019 unguarded-token-send

**Severity:** high · **Confidence:** medium · **Applies to:** Compact

## What it finds

An exported circuit that sends tokens (`sendShielded`, `sendUnshielded`, `send`, `sendImmediate`), directly or through a helper, with no check that could identify the caller.

## Why it matters

Anyone can call an exported circuit. Without a caller check, anyone can move the contract's funds to any address.

## Example

```compact
export circuit pay(a: Uint<64>, to: UserAddress): [] {
  sendUnshielded(default<Bytes<32>>, disclose(a) as Uint<128>, right<ContractAddress, UserAddress>(disclose(to)));
}
```

## Fix

```compact
assert(deriveId(secretKey()) == ownerId, "not the owner");
sendUnshielded(…);
```

## Not flagged / known limits

A check counts when an assert involves a witness, a ledger value, ownPublicKey() or a helper circuit, or when the circuit calls code from another module (which may check the caller). An assert on parameters only (`assert(amount <= 100)`) does not count. Circuits named `_like_this` (the convention for unchecked building blocks) are skipped.
